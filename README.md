# واریسک

> محاسبهٔ ارزش در معرض خطر (VaR) پارامتریک پرتفوی سهام در مرورگر، هم‌زمان با تایپ.

نرم‌افزار تحت‌وب برای سنجش ریسک بازار با رویکرد ماتریس واریانس-کوواریانس. تمامی محاسبات
آماری به صورت بلادرنگ و کاملاً سمت کلاینت در مرورگر کاربر انجام می‌شود — هیچ سری قیمتی
به سرور ارسال نمی‌شود و سرور فقط جهت ذخیره‌سازی اختیاری پرتفوی‌ها کاربرد دارد.

## مبانی محاسباتی و فرضیات مدل

1. **رویکرد واریانس-کوواریانس (Parametric VaR):** بازدهی دارایی‌ها به صورت ساده ($R_t = \frac{P_t - P_{t-1}}{P_{t-1}}$) محاسبه شده و ماتریس کوواریانس نمونه با مخرج $N-1$ ساخته می‌شود. ریسک کل پرتفوی از رابطهٔ $\sigma_p = \sqrt{w^T \Sigma w}$ به دست می‌آید.
2. **محاسبهٔ دقیق صدک‌های توزیع نرمال:** به جای مقادیر گردشدهٔ کتابی، از پیاده‌سازی دقیق الگوریتم Peter J. Acklam برای تابع معکوس توزیع نرمال ($\Phi^{-1}(p)$) استفاده می‌شود که در سراسر بازه خطای نسبی کمتر از $1.15 \times 10^{-9}$ دارد و با `scipy.stats.norm.ppf` پایتون و تابع `NORM.S.INV` اکسل کاملاً منطبق است.
3. **فرض میانگین در افق کوتاه‌مدت:** طبق رویهٔ متداول تحلیل ریسک معاملاتی، میانگین بازدهی در افق‌های روزانه در برابر نوسان‌پذیری ناچیز شمرده شده و اثر آن در سطح زیان حذف می‌شود.
4. **مقیاس‌دهی افق زمانی (قاعده جذر زمان):** ارزش در معرض خطر برای هر افق $h$ روزه با قاعدهٔ استاندارد کمیتهٔ بال مقیاس‌دهی می‌شود ($VaR_h = VaR_1 \times \sqrt{h}$)، از جمله افق ۱ روزه معاملاتی و افق ۱۰ روزه مقرراتی بال.
5. **اعتبارسنجی مستقل:** کلیهٔ محاسبات ماتریسی و آماری به طور خودکار در برابر توابع مرجع NumPy، SciPy و اکسل آزموده شده و تست‌های بنچ‌مارک آن در مخزن موجود است.

## راه‌اندازی

```bash
npm install
```

`.env.example` را به `.env.local` کپی و پر کنید — برای توسعه، `NUXT_TURSO_URL`
می‌تواند یک فایل محلی باشد و به هیچ حساب Turso نیاز نیست. بعد جدول‌ها را بسازید:

```bash
npm run db:migrate
```

```bash
npm run dev
```

روی `http://localhost:3001` بالا می‌آید. پورت ۳۰۰۱ عمدی است — در
[`nuxt.config.ts`](nuxt.config.ts) قابل تغییر است.

## متغیرهای محیطی

در `.env.local`؛ روی Vercel همین سه نام در تنظیمات پروژه ست می‌شوند. پیشوند
`NUXT_` عمدی است: مقدارها در زمان اجرا خوانده می‌شوند، نه در بیلد، پس چرخاندن
توکن به دیپلوی دوباره نیاز ندارد.

| نام | کار |
|---|---|
| `NUXT_TURSO_URL` | نشانی دیتابیس؛ `file:.data/varisk.db` برای توسعه |
| `NUXT_TURSO_AUTH_TOKEN` | توکن Turso؛ برای نشانی فایلی لازم نیست |
| `NUXT_JWT_SECRET` | کلید امضای کوکی نشست؛ عوض کردنش همه را خارج می‌کند |

## تغییر نام و برند

نام محصول و نام سازنده هر دو در [`app/utils/content.ts`](app/utils/content.ts)
به‌صورت `SITE_NAME` و `BUILDER` تعریف شده‌اند؛ هدر، فوتر و عنوان صفحه‌ها همه از
همان‌جا رندر می‌شوند.

پالت رنگ و فونت در [`app/assets/css/main.css`](app/assets/css/main.css) به‌صورت
متغیرهای CSS قفل شده‌اند. هر رنگ دو پله دارد: `--bg` و هم‌خانواده‌هایش مقدار خام
را نگه می‌دارند و با تم عوض می‌شوند، `--color-*` همان را به Tailwind می‌دهد. یک
اتریبیوت روی `<html>` کل برنامه را بازرنگ می‌کند.

## استقرار

پروژه به Vercel متصل است و هر پوش روی شاخهٔ اصلی به‌صورت خودکار منتشر می‌شود.
پیش از اولین انتشار، سه متغیر بالا باید در تنظیمات پروژه ست شده باشند.

خروجی یک سرور Nitro است، پس هر میزبان Node هم کار می‌کند:

```bash
npm run build
```

```bash
node .output/server/index.mjs
```

### دامنه

یکی از `varisk.ir` و `www.varisk.ir` باید کانونی باشد و آن یکی با ۳۰۱ به آن
برود. کوکی نشست به هاست چسبیده است: کسی که روی یکی وارد شده، روی دیگری وارد
نیست. `runtimeConfig.public.siteUrl` در [`nuxt.config.ts`](nuxt.config.ts) می‌گوید
کدام کانونی است.
